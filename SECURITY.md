# Security Policy

## Reporting a vulnerability

Do not disclose vulnerabilities in a public issue, discussion, pull request, commit, or chat channel.

Report suspected vulnerabilities privately to the designated HellCold security contact or through GitHub Private Vulnerability Reporting when it is enabled for the affected repository. Include:

- affected repository and version or commit;
- a concise description and potential impact;
- reproducible steps or proof of concept;
- suggested mitigation, if known;
- whether the issue is already public.

Do not include live credentials, customer data, personal data, or production exports in the report. Revoke exposed credentials immediately and notify the system owner.

## Supported versions

Unless a repository states otherwise, only the latest production release and the current `main` branch receive security fixes.

## Response

HellCold will acknowledge a valid report, assess severity, coordinate remediation, and disclose information only after an appropriate fix or mitigation is available.
