# Contributing to HellCold repositories

## Workflow

1. Create or reference a GitHub Issue for a meaningful change.
2. Create a short-lived branch from `main` using an allowed prefix:
   - `feat/`
   - `fix/`
   - `docs/`
   - `refactor/`
   - `test/`
   - `chore/`
   - `hotfix/`
3. Keep the change focused on one purpose.
4. Use an English Conventional Commit message: `<type>(<scope>): <description>`.
5. Open a Pull Request and complete every applicable section.
6. Resolve review comments and wait for required checks and approvals.
7. Merge only through the method allowed by the repository ruleset.

## Required quality

Every change must be reviewed, tested, secure, documented, and reversible. AI-generated code is subject to the same requirements as manually written code.

## Prohibited content

Do not commit credentials, tokens, passwords, production certificates, personal data, customer data, financial data, database dumps, production telemetry, or project BIM deliverables. Store business data in Business Central, BIM/CDE information in Autodesk ACC, analytical data in watsonx.data, office documents in SharePoint, and secrets in HashiCorp Vault.

## Internal standard

Organization members must also follow the approved private HellCold GitHub Repository Standard, HC-STD-GIT-001.
